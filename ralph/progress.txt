## Codebase Patterns
- Use `dataclasses` with `field(default_factory=dict)` for mutable defaults
- Type annotations must use `dict[str, Any]` instead of bare `dict` for mypy --strict
- Return defensive copies from `to_dict()` methods (e.g., `dict(self.info)`)
- Tests use pytest with descriptive test names and docstrings
- All model objects have: name, label (optional), description (optional), info (default {})
- Label generation: replace underscores with spaces, capitalize first letter only
- **Important**: Cannot inherit from ModelObject if subclass needs required fields (dataclass constraint)
  - Instead, duplicate name/label/description/info fields directly in the subclass
  - This is a Python dataclass limitation: fields without defaults cannot follow fields with defaults
- Use `Union[Attribute, str, None]` type for init parameters that accept string references
  - Resolve to Attribute in `__post_init__` using `isinstance()` checks
- Use `object.__setattr__()` to set frozen/final fields in `__post_init__`
- **When filtering dataclass fields, also update the field values, not just internal dicts**
  - Example: After filtering `_level_dict`, also update `self.levels` field
  - Otherwise property access returns stale data
- **Template inheritance in from_schema(): explicit levels replace template levels entirely**
  - Don't append to template levels - replace them to avoid duplicates
- **Level filtering: dimension only keeps levels actually used in hierarchies**
  - __post_init__ filters levels to those referenced by at least one hierarchy
  - This matches legacy behavior where unused levels are discarded
- **MetadataProvider is an abstract base class using ABC and @abstractmethod**
  - Subclasses must implement list_cubes(), has_cube(), cube(), and dimension()
  - Template resolution uses _pending set for cycle detection
  - Check templates dict is not None before membership testing: `if templates and template_name in templates`
